# Decisions

| Date | Decision | Why | By |
|---|---|---|---|
| 2026-11-17 | First month: `exact` scheme on EVM (EIP-3009) and Solana; HTTP and MCP transports; x402 v1 and v2. Everything else refused. | Depth before breadth; each branch is a new way to sign money away. | owner |
| 2026-11-17 | At most 4 agents at a time; pipeline runs as a scripted workflow. | Cost and machine load; steps cannot be skipped. | owner |
| 2026-11-17 | Developed in public on GitHub. | Owner's choice. | owner |
| 2026-11-17 | Week 1 contracts M1–M4 frozen (`contracts/`, `src/types.ts`). | Builders and testers must work from the same fixed text. | dispatcher |
| 2026-11-17 | Solana `validUntil` = now + 120 s (blockhash lifetime, conservative); durable nonces refused. | The message has no explicit expiry; a durable nonce would make a payment valid indefinitely. | dispatcher |
| 2026-11-17 | Stablecoins only (`usd_per_unit`), USD in millionths, rounded up. | No price oracle in week 1; rounding up never lets a budget be exceeded. | dispatcher |
| 2026-11-18 | M2: domain FORMAT checks (chainId, verifyingContract) run first, then TYPE, then message FORMAT checks. `domain.chainId` may be number, bigint or decimal string if it is a safe positive integer. `from == to`, `value == 0` and `validBefore > MAX_SAFE_INTEGER` are FORMAT and run before ASSET. | The contract put FORMAT before TYPE, which would report a Permit as FORMAT instead of TYPE. Builder's reading accepted. | dispatcher |
| 2026-11-18 | M1: `AMOUNT` minimum in atoms = ceil(min_usd6 × 10^decimals / price_usd6); `usd_per_unit` of 0 → `AMOUNT`. A malformed decimal string in the policy throws (policy is validated at load, not per payment). Pin comparison uses the allowlist normalization (EVM lowercase, Solana exact). | Contract silent; fail-closed readings accepted. | dispatcher |
| 2026-11-18 | M3: System discriminator 4 (AdvanceNonceAccount) → `LIFETIME`, any other System instruction → `INSTRUCTION`; compute-budget with wrong data length or accounts → `INSTRUCTION`; 0 or ≥2 `TransferChecked` → `INSTRUCTION`; fewer than 4 transfer accounts or out-of-range indices → `FORMAT`; more than 4 → `INSTRUCTION`; trailing bytes → `FORMAT`; wrong authority → `SENDER` before the payer-elsewhere rule; payer not signer or writable → `INSTRUCTION`; v1 messages carry compute budget in config, so only transfer and memo instructions are allowed there. | Contract silent; fail-closed readings accepted. Testers must use these rules. | dispatcher |
| 2026-11-18 | M4: `markUndelivered` stores host and ts; an allow with negative usd6 throws and rolls back; any call on a closed store throws; PRAGMA user_version holds the schema version; synchronous=FULL. | Contract silent; fail-closed readings accepted. | dispatcher |
| 2026-11-18 | Build first, test in a separate later step (owner: save tokens). Builders ran on a cheaper model; code is unverified until the test step. | Owner's choice. | owner |
| 2026-11-18 | Readers return `signable`, the only thing a signer may sign (#14). EVM: frozen `{domain: {name, version, chainId: bigint, verifyingContract}, primaryType, message}` built from a `structuredClone` snapshot of the input (getters run once, proxies → `FORMAT`). Solana: a private copy of the message bytes. | Attack review showed a getter/Proxy message could pass the reader and sign different values. | dispatcher |
| 2026-11-18 | M2: domain may contain only `name`, `version`, `chainId`, `verifyingContract`; any other key → `FORMAT`. `name` and `version` must be strings → `FORMAT`, checked after `TYPE` (so Permit2, which has no version, stays `TYPE`). | Extra keys or a string chainId would change the signed EIP-712 domain (#15). | dispatcher |
| 2026-11-18 | M3: a non-bytes input or an invalid `payTo` address → `FORMAT` instead of a throw. | #16. | dispatcher |
| 2026-11-18 | M1 adds `checkPolicy(policy)` (throws at load: non-positive windows; `max_validity_s < 120` with a Solana network) and `minPruneKeepS(policy)`; callers must never prune with a smaller `keepS`. | #17: operator settings that silently disable Solana or erase counted spend. | dispatcher |
| 2026-11-18 | M5: keys created with node:crypto (ed25519) and viem; dir and files checked with `lstat` (symlinks refused), dir `mode & 077 == 0`, files exactly 0600, created with `wx`, never chmodded; a missing second key file is created, the existing one kept. EVM signer exposes only `address` and `signTypedData`; Solana signer refuses 0 or ≥2 transactions before the gate runs. | Contract silent; fail-closed readings accepted. | dispatcher |
| 2026-11-18 | M6: fresh `x402Client`, signer and one-shot gate per request (second gate call → REPLAY); x402 v2 only (v1 → NETWORK); x402's own $1 spend controls switched off because the policy replaces them; `/fetch` answers HTTP 200 with the seller status inside; undelivered = status ≥ 400, 3xx, missing or failed settlement header; Host header must be loopback (DNS rebinding); `listen.host` must be 127.x or ::1; store pruned with `minPruneKeepS` at start and hourly; `assets` only at top level of the config. | Contract silent or loose; stricter readings accepted. | dispatcher |
| 2026-11-18 | M11: one seller port per scenario (pins, budgets and non-delivery blocks are per host:port); the payee-switch demo is `/switch` then `/switch-b` on the same port. M10 reads budget and window from `?budget=&window=` (defaults 0.10 / 3600). | Offline run showed one scenario's block hiding the next. | dispatcher |
| 2026-11-18 | SSRF guard (#8): every outbound connection's resolved address is checked in its own DNS lookup (no check-then-resolve gap); private, loopback, link-local, CGNAT, documentation, multicast and reserved ranges refused as `HOST`; `allowPrivateHosts` exempts exact `host:port` entries for the local bench. | A compromised agent could make the firewall read internal services or cloud metadata. | dispatcher |
| 2026-11-18 | Unsettled authorizations stay counted against the budget until they expire (#15). The intermittent 402s were the public facilitator failing to submit its own transaction (`invalid_exact_evm_transaction_failed`, RPC "Missing or invalid parameters"); the firewall now logs that reason. | A signed EIP-3009 authorization remains valid for the seller until `validBefore`; releasing it early would let real spend exceed the budget. | dispatcher |
| 2026-11-18 | Paid-response cache in memory only, keyed by (agent, full URL), off by default (`cache_ttl_s: 0`), 500 entries, oldest evicted, lost on restart. Only delivered paid responses are stored; a hit signs nothing and contacts no seller. | Repeat purchases of the same URL are the cheapest waste to remove; memory-only keeps bodies off disk and the log free of content. Stale data within the TTL is the owner's trade-off, hence default off. | dispatcher |
| 2026-11-18 | Cached hits are logged as `allow: true, cached: true` with the first price in `usd6`, and are excluded from `spentUsd6` and the dashboard "Spent". | The log shows what was saved; budget counting stays equal to what was signed. | dispatcher |
| 2026-11-18 | `GET /report` is computed from the decision log (per agent, window clamped to 30 days, bad values 400) and `budgetUsd6` = min(agent budget, global budget). | The log is the account the owner reads; the agent should see the limit that will bind first. | dispatcher |
| 2026-11-18 | Catalog price check runs after the requirement is chosen and before the gate; overpriced -> new refusal code `OVERPRICED` with reason `asks Nx the catalog price` (no policy numbers). A payee that differs from the catalog is only flagged (`catalogPayeeChanged`), not refused. | Pinning and the allowlist already decide payees; a catalog is a hint, so it may only add a refusal for price, never loosen a rule. | dispatcher |
| 2026-11-18 | The firewall loads `catalog.json` read-only, re-checks its mtime at most every 60 s and never downloads; refresh stays an owner command. `/search` answers 503 without a catalog and caps `limit` at 25 and descriptions at 200 chars. | No network at start, no surprise 30 MB download inside the payment process; catalog text is untrusted. | dispatcher |
| 2026-11-18 | `find_paid_resources` marks results `[payable]` / `[not payable]` against the live policy and always ends with an unverified-text reminder. | The agent should not pick a service the firewall will refuse, and must not treat seller text as instructions. | dispatcher |
| 2026-11-19 | M8: console disabled (all `/admin/*` 404) when `adminTokenSha256` is absent or still the example placeholder `REPLACE_WITH…`; any other non-hex value is a config error. | A copied example config must start safely, but a typo in a real hash must not silently disable auth. | dispatcher |
| 2026-11-19 | M8: an approval is the normal reservation held open: the spend row is written when the policy allows, then removed by `FirewallStore.releaseSpend` on deny, timeout, overflow or shutdown. The payee pin written with the reservation is kept (a denied first payment still pins that payee). | Parallel requests cannot overshoot while one waits; keeping the pin fails closed. | dispatcher |
| 2026-11-19 | M8: revoking removes the token hashes from the config file and adds the id to `revokedAgents`; the id stays in `policy.agents` so history and reports still resolve, and the id cannot be reused (409). | Revoked agents must stay listable; a reused id would inherit old log lines. | dispatcher |
| 2026-11-19 | M8: `PUT /admin/rules` merges the body into the running values, validates relations only for the keys involved, runs `checkPolicy` on the merged policy, writes the file (tmp + rename, 0600, other keys untouched) and only then mutates memory, synchronously. A file write failure answers 500 with nothing changed. | No request sees a half-applied rule set and file and memory never disagree. | dispatcher |
| 2026-11-19 | M8: CSV export is chronological (oldest first), decision is `allow`, `cached` or `refuse`; cells starting with `= + - @`, tab or CR get a leading `'`. `FirewallOptions.approvalTimeoutMs` (tests only) overrides `approval_timeout_s`; `GET /admin/state` also returns `approval_timeout_s`. | Contract left these open. | dispatcher |
| 2026-11-19 | `npm start` (`src/start.ts`, `src/setup.ts`): first run writes `config.json`, `agent.token` and `admin.token` (0600, in a 0700 folder, `ASF_DIR` overrides the place), never overwrites any of them, and the config holds only the sha256 of each token. | One command has to be enough to try the product; an existing setup must survive a second run untouched. | dispatcher |
| 2026-11-19 | `npm start` signs the console in by opening `/app#k=<admin token>`; the page reads the fragment, stores the token in `sessionStorage` and removes it from the address with `history.replaceState` before doing anything else. The terminal never prints a token. | A fragment is not sent to the server or to any other site, and a pasted token is the main thing a first-time user gets wrong. Cost: the token is briefly an argument of the local `open` command, visible to processes of the same machine. Acceptable for a loopback-only, testnet-only tool; revisit before mainnet. | dispatcher |
| 2026-11-19 | `--practice` allowlists the four loopback practice ports in memory for that run only; the generated config keeps `allowPrivateHosts` empty. | The SSRF guard should not be weakened on disk by trying the product once. | dispatcher |
