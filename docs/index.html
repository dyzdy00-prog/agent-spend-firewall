Pay

fetch_paid_resource(url)

Fetches the URL. On 402 Payment Required the firewall checks the exact bytes against your rules and the catalog price, signs once, and returns the content.

$0 for a repeat: an answer already paid for is served from the cache.

buys the cheapest listing that delivers

One payment, five checks, a few milliseconds.

The firewall never trusts a description of a payment. It reads the exact bytes it is about to sign.

1
The agent calls the tool

fetch_paid_resource(url) over MCP, with its token. It has no key to send.

2
The firewall fetches

The seller answers HTTP 402 with a price. Redirects and internal addresses stop here.

3
It reads the bytes

Amount, asset, recipient, expiry: decoded from what would be signed.

4
It checks your rules

Cap, budgets, payee, validity, replay and delivery history, in one atomic step.

5
It signs, or it doesn't

One signature for what passed. Every decision goes to the ledger.

We tested the standard x402 client before writing a line.

An agent holding a funded key, with the client's default settings.

Do not take our word for it

These payments are on a public blockchain. The button asks a public Base Sepolia node for each receipt, from your browser, and checks that the money left the firewall's wallet and reached the seller.

What you are looking at

  • Six payments settled and were delivered. Their transaction links are in the log.
  • Four were signed but not completed: two by a seller that returns errors, two because the public test facilitator failed to submit them. The firewall keeps counting them until they expire.
  • Five were refused before signing: over the cap, wrong payee, a seller that does not deliver, an internal address, and the budget.

What is live, and what is not yet.

  
An MVP on testnets, built in public. Not audited. Do not use it with real keys or real money.

LIVERefuses quotes far above the catalog price; serves repeat requests from cache at no cost

    
LIVEBetween payments: a new seller gets small payments until it delivers once; the same address asking far more than last time is refused; an empty answer counts as not delivered; two requests for the same thing at once are paid once, also across agents if you allow it

cd agent-spend-firewall
npm ci --ignore-scripts
npm start

npm start -- --practice
