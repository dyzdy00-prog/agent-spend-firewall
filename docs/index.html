Let AI agents pay — without handing them your wallet.

Agents now buy API calls, data and compute on their own over x402. Agent Spend Firewall keeps the key and the spending rules in a separate process the agent cannot touch. You set the budget once; every payment is checked before it is signed.

Run the demo View on GitHub

Today an agent with a key can spend whatever it is told to.

x402 makes paying for a web request as easy as making it. That is the point — and the risk. A prompt injection, a buggy loop or a dishonest seller turns an agent's wallet into an open tab. We measured what the official x402 client does by default:

$99signed for 100 calls to a page that advertised $0.01 per call — each charge stayed under the $1 per-payment default
10 yearsvalidity on a payment authorization the client was willing to sign
0limits on total spend over time, or on who gets paid, unless the developer writes them — inside the same agent an attacker controls

What you get

Give agents a spending allowance the way a company gives an employee a card with a limit — enforced somewhere the agent cannot reach.

A hard ceiling on spend

Per-payment cap and rolling budgets per agent, per seller and in total. When the budget is used up, nothing more is signed — however the agent is prompted.

The key never enters the agent

The agent holds only a revocable token. A compromised agent can ask; it cannot sign, raise its own limits, or read the key.

Pay the right people

Payees are pinned per seller on first payment, or fixed by an allowlist. If a seller suddenly asks to be paid elsewhere, the payment is refused.

No delivery, no more payments

A seller that takes payment and returns an error gets blocked after a few tries, so a broken or dishonest endpoint cannot drain the budget.

Every decision on record

An append-only log and a live dashboard show what was paid, what was refused and why, with links to each settled transaction. No keys, tokens or URL paths are stored.

Works with the agent you have

One MCP tool — fetch_paid_resource(url) — for Claude or any MCP client, or a plain HTTP call. No changes to the sellers you pay.

WITHOUT

An agent with a funded key

  • Limits are code inside the agent — and can be talked out of it
  • Prompt injection can redirect payments to any address
  • Long-lived authorizations keep working after you notice
  • You find out from the balance
WITH THE FIREWALL

An agent with an allowance

  • Limits live in a separate process with the key
  • Unknown or changed payees are refused before signing
  • Validity is capped; replays are refused
  • You see every decision as it happens

Built for teams running agents that buy APIs, data, search or compute per call; for platforms that give many agents their own budgets; and for anyone who wants an agent to pay without trusting it with money.

How it works

The firewall sits between the agent and the paid web. It reads the exact bytes it is about to sign — the EIP-712 authorization on EVM, the transaction message on Solana — not a description of them.

Agent asks“Fetch this URL” with its token. No key.
Firewall fetchesGets the 402 price itself; refuses redirects and internal addresses.
Reads the bytesDecodes exactly what would be signed; anything unexpected is refused.
Checks the policyCap, budgets, payee, validity, replay, delivery history — atomically.
Signs or refusesSigns only what passed, pays once, records the outcome.

What it refuses

CAPA single payment above your per-payment limit.
BUDGETTotal, per-agent or per-seller spend above the budget for the window.
PAYEEA payee not on the allowlist, or different from the one first paid on that seller.
UNDELIVEREDA seller that already took payment without delivering.
VALIDITYAn authorization that would stay valid longer than you allow.
REPLAYThe same authorization presented twice, or too many signatures in the window.
HOSTRedirects and loopback, private or cloud-metadata addresses (SSRF).
MISMATCHSigned bytes that differ from what the seller asked for — amount, asset, recipient, chain.

Get started

The demo runs a test seller, the firewall and an agent on your machine and pays on Base Sepolia with free test USDC.

git clone https://github.com/dyzdy00-prog/agent-spend-firewall
cd agent-spend-firewall
npm ci --ignore-scripts
npm run demo     # prints your test address; fund it
                 # at faucet.circle.com, run again

Plug in your agent

Add one MCP server. The agent sees a single tool and holds only a token.

{ "mcpServers": { "spend-firewall": {
  "command": "node",
  "args": ["agent-spend-firewall/src/mcp.ts"],
  "env": { "ASF_AGENT_TOKEN_FILE":
           "~/.agent-spend-firewall/agent.token" }
} } }

This is an MVP on testnets. It has not been audited. Do not use it with real keys or real money yet. Supported today: x402 v2 exact payments with USDC on Base Sepolia and Solana devnet. Built in public: specs, decisions and 500+ tests are in the repository.
