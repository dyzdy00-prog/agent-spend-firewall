The MCP server for x402 payments · spend control for AI agents

This hour your agent asked to spend $0.00. The firewall signed $0.00.

x402 lets an AI agent pay for an API call the moment a server asks. Add this firewall to Claude, or any MCP agent, as one tool: the agent pays through it, while the key and your rules stay in a separate process. The agent can ask. It cannot sign.

One MCP tool. That is the whole integration.

Your agent gets fetch_paid_resource(url). When a server replies 402 Payment Required, the firewall pays it over x402 if your rules allow, and hands the agent the content. If not, the agent gets a plain refusal it can report.

One payment, five checks, a few milliseconds.

The firewall never trusts a description of a payment. It reads the exact bytes it is about to sign.

1
The agent calls the tool

fetch_paid_resource(url) over MCP, with its token. It has no key to send.

2
The firewall fetches

The seller answers HTTP 402 with a price. Redirects and internal addresses stop here.

3
It reads the bytes

Amount, asset, recipient, expiry: decoded from what would be signed.

4
It checks your rules

Cap, budgets, payee, validity, replay and delivery history, in one atomic step.

5
It signs, or it doesn't

One signature for what passed. Every decision goes to the ledger.

What changes when the rules live outside the agent.

For teams whose agents buy data, search or compute per call, and for platforms that give many agents a budget each.

A ceiling that holds

A cap per payment and a budget per hour, per agent and per seller. When it is used up, nothing more is signed, whatever the agent is told.

You see it: attacks 02 and 04, and the meter.

The key never visits the agent

The agent holds a token you can revoke. A hijacked agent can keep asking. It cannot sign, read the key or raise its own limit.

You see it: the vault under the gate.

Money goes where it went before

The first payment to a seller pins its payout address, or you fix it with an allowlist. A different address is refused.

You see it: attack 03.

No delivery, no second chance

A seller that takes payment and returns an error is blocked after a few strikes, before it drains the budget.

You see it: attack 05.

A record you can read

Every payment and every refusal, with the reason and a link to the transaction. No keys, tokens or URL paths are stored.

You see it: the ledger, and the dashboard below.

Nothing to rebuild

One MCP tool for Claude or any MCP client, or one HTTP call. Sellers change nothing.
